|--------|-----------|---------|

## Complete Fork Workflow (Step 3 — repo_service.ForkRepository)

The fork operation is a multi-step process that makes these external/system calls in sequence:

1. Database operations — Check user block, check repo limit, check existing fork, create repo in DB (transaction), increment fork count
2. Git clone bare (External Call #1) — Clone source repo to local filesystem
3. Update git repo — Configure the new bare repository
4. Create hooks — Write git hooks to the filesystem
5. Copy LFS — Copy LFS meta objects (DB) and potentially push to remote (External Call #2)
6. Sync branches — Sync branch records to DB
7. Sync releases/tags — Sync release and tag records
8. Update repo size — Calculate and store repository size
9. Copy language stats — Copy language statistics
10. Copy license — Copy license information
11. Set status ready — Mark repository as ready in DB
12. Notify — Send notification (internal event system)

## Cascading Failure Risks

- **Many concurrent fork requests → disk I/O saturation → all git operations slow down** (documented cascading failure scenario)
- The non-atomic nature means: DB insert → git clone → sync branches — if clone fails after DB insert, cleanup runs but could leave partial state if cleanup itself fails
