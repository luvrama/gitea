The main categories are:

**1. HTTP Git Smart Protocol (direct git transport)**
- POST /git-upload-pack → `git upload-pack --stateless-rpc .`
- POST /git-receive-pack → `git receive-pack --stateless-rpc .`
- GET ?service=git-upload-pack (GetInfoRefs) → `git upload-pack --advertise-refs .`
- GET ?service=git-receive-pack (GetInfoRefs) → `git receive-pack --advertise-refs .`

**2. File Content Modification (Create/Update/Delete/ChangeFiles)**
- POST /api/v1/repos/{owner}/{repo}/contents (ChangeFiles)
- POST /api/v1/repos/{owner}/{repo}/contents/{filepath} (CreateFile)
- PUT /api/v1/repos/{owner}/{repo}/contents/{filepath} (UpdateFile)
- DELETE /api/v1/repos/{owner}/{repo}/contents/{filepath} (DeleteFile)

These all go through `ChangeRepoFiles` → `TemporaryUploadRepository`:
- `git clone -s` (via CloneRepoToLocal)
- `git read-tree HEAD`
- `git update-index --refresh`
- `git ls-files -z`
- `git hash-object -w --stdin`
- `git update-index --add --replace --cacheinfo`
- `git write-tree`
- `git commit-tree`
- `git push`

**3. Apply Diff Patch**
- POST /api/v1/repos/{owner}/{repo}/diffpatch (ApplyDiffPatch)
- `git clone -s`
- `git read-tree HEAD`
- `git apply --index --recount --cached --ignore-whitespace --whitespace=fix --binary`
- `git write-tree`
- `git commit-tree`
- `git push`

**4. Pull Request Merge**
- POST /api/v1/repos/{owner}/{repo}/pulls/{index}/merge (MergePullRequest)
- `git init`, `git remote add`, `git fetch`, `git symbolic-ref HEAD`
- Then depending on merge style:
  - merge: `git merge --no-ff --no-commit` + `git commit`
  - rebase: `git rebase` + `git merge --ff-only` or `git merge --no-ff --no-commit`
  - squash: `git merge --squash` + `git commit`
  - fast-forward-only: `git merge --ff-only`
- Finally: `git push origin base:refs/heads/<branch>`

**5. Branch Operations**
- POST /api/v1/repos/{owner}/{repo}/branches (CreateBranch)
  → `git push` (via `CreateNewBranchFromCommit` → `gitrepo.Push`)
- DELETE /api/v1/repos/{owner}/{repo}/branches/{branch} (DeleteBranch)
  → `git branch -D <name>`
- PUT /api/v1/repos/{owner}/{repo}/branches/{branch} (UpdateBranch) - not sure what this does exactly
- PATCH /api/v1/repos/{owner}/{repo}/branches/{branch} (RenameBranch)
  → `git branch -m <from> <to>`

**6. Tag Operations**
- POST /api/v1/repos/{owner}/{repo}/tags (CreateTag)
  → `git tag <name> <revision>` or `git tag -a -m <message> <name> <revision>`
- DELETE /api/v1/repos/{owner}/{repo}/tags/{tag} (DeleteTag)

**7. Fork**
- POST /api/v1/repos/{owner}/{repo}/forks (CreateFork)
  → `git clone --bare` (timeout: 10 minutes)

**8. Repository Migration**
- POST /api/v1/repos/migrate (Migrate)
  → `git clone --mirror` (timeout: `setting.Git.Timeout.Migrate` * time.Second, default 600s/10min)

**9. Merge Upstream**
- POST /api/v1/repos/{owner}/{repo}/merge-upstream (MergeUpstream)
  → First attempts `git push` (fast-forward), if that fails does full merge via PR machinery

**10. Archive Download**
- GET /api/v1/repos/{owner}/{repo}/archive/{archive} (GetArchive)
  → `git archive --format=<format> <commitID>` or bundle creation

**11. Mirror Sync (via Cron/Admin API)**
- `git fetch --tags <remote>` (timeout: `setting.Git.Timeout.Mirror` * time.Second, default 300s/5min)
- `git remote prune <remote>` (timeout: same as Mirror)
- `git push --mirror` (timeout: same as Mirror)

**12. Git GC (via Cron/Admin API)**
- `git gc` (timeout: `setting.Git.Timeout.GC` * time.Second, default 60s)

**13. Git Fsck (via Cron/Admin API)**
- `git fsck` (timeout: `setting.Git.Timeout.GC` * time.Second, default 60s)

**14. Wiki Operations**
- POST /api/v1/repos/{owner}/{repo}/wiki/new (CreateWikiPage)
- PATCH /api/v1/repos/{owner}/{repo}/wiki/page/{pageName} (EditWikiPage)
- DELETE /api/v1/repos/{owner}/{repo}/wiki/page/{pageName} (DeleteWikiPage)
  → `git clone -s`, various index operations, `git commit-tree`, `git push`

Now for timeouts:
- Most operations that go through TemporaryUploadRepository have NO explicit timeout (uses process manager context)
- Clone for fork: 10 minutes
- Clone for migration: `setting.Git.Timeout.Migrate` (default 600s = 10 minutes)
- Mirror sync: `setting.Git.Timeout.Mirror` (default 300s = 5 minutes)

[38;5;252m[1m## Key Observations[0m[0m
[0m[0m
1. [1mMost API-triggered git operations have NO explicit timeout[22m — they rely solely on the HTTP request context lifetime. This means long-running git operations on large repositories could block indefinitely.[0m[0m
